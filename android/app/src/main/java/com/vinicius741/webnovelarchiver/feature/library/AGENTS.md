# Library

Applies to `feature/library/` (the Library root, Add story, the author page). These rules add to `android/AGENTS.md`.

- **Model and renderer.**
  - `LibraryScreenModel` (from `libraryModel()`, keyed by `AppRoute.Library`; the Library is the root of every history, so it lives as long as the activity) publishes `LibraryUiState`: the repository's published library (`LibraryStories`, the shared `downloadState.library` list, compared by identity and never copied), tabs and pager pages, the filter (search, tags, resolved tab, sort), the open search, the layout, multi-select, and the Continue listening card. It follows the library (by `libraryVersion`) and playback only while a renderer collects `state`; a render starts from `onRender()`, which also takes the latest library and looks the card up again. Reads and writes go through `LibraryData` (`HostLibraryData`; fake it in tests).
  - Preference changes (tab, sort, layout, card dismissal) apply to the state at once and save in the background; a failed save comes out of `messages` and the saved value applies again. A tab picked on the screen stays picked (Unassigned included, which the saved preference stores as All).
  - `showLibrary` starts a `LibraryRenderer`. A new `LibraryBuildKey` (selection or search starting or ending, the layout, the page set, empty or not) rebuilds the screen; anything else is patched: filters re-filter the bound pages (the search after a 200 ms pause), a selection change rebinds only the toggled card on every page (all cards for Select all), a library change hands the new list to the adapters and patches only the coverage of stories whose counts moved (no rebind during a gesture), and the Continue listening card binds its slot. Cards read their selection and send taps through `LibraryCardEvents`.
  - Cards and cover tiles (`LibraryStoryCard`, `LibraryCoverTile`, `LibraryCardView`) build their view tree once per holder and rebind values into it: optional lines and badges are hidden (GONE), never removed, and the meta row rebuilds its pills only when its `LibraryBadgeKey` changes. Story list changes reach the adapter through `LibraryCardDiff` (moves, arrivals and departures by id; a change only where `LibraryCardContent`, every field a card shows except chapter coverage, differs), so a download tick rebinds nothing and `patchLibraryProgress` still patches the tagged coverage views. A move keeps the first visible row index, as the full rebind it replaced did. Add any new field a card shows to `LibraryCardContent`.
  - A rebind ends with `remeasureLibraryCard` (a reused title otherwise kept the previous story's line height), and `LibraryCoverSlot` clears the reused cover view's bounds before loading: Coil sizes a load from the view, a reused view still has its previous column's size, and columns differ by a pixel. Check recycled holders (scroll far and fling back) against fresh ones when changing card binding.
  - Selection actions are model actions (`downloadSelected`, `deleteSelected`, `moveSelected`); the renderer keeps the confirm, the move sheet and the toasts. System Back closes selection (`closeAction`), then clears the search and tags (`BackIntercept` on `backClears`); the renderer calls `refreshBackCallback()` when `backClears` changes.
  - Per-tab scroll offsets live in the model (`rememberScroll`/`scrollOffset`, keyed by `LibraryTabSelection.memoryKey`), not in `RouteViewMemory`. The query, tags and offsets survive a process death through `LibraryScreenStatePersistence`, which saves the model's `savedState()` and hands the restored state to `ScreenModelStore.restore`, where the model's first creation takes it.
  - The open Sort & filter sheet closes when the render's root detaches (fold, search, selection).
- `AddStoryScreenModel` (keyed by `AppRoute.AddStory`) holds the URL draft, the "Save to tab" pick and the fetch status, so the draft lasts while Add story is in the history and a fresh open starts empty. A new status or tab pick rebuilds the form; typing does not. The fetch itself is `feature/story/syncStory`, whose callbacks update the model and open the story when it is added.
- `LocalLibraryScreenModel` (keyed by `AppRoute.LocalLibrary`) holds the folder scan, the in-library marks and the import in progress, with the "Add all" queue; `showLocalLibrary(host)` renders it with a `LocalLibraryRenderer`, which starts each import through `feature/story/syncStory` (as Add story does) and registers the folder picker on the activity's result registry for one pick only.
- `AuthorNovelsScreenModel` computes the author's other novels from the published library on each render; it does not follow the library live.
- Filtering, sort and tab rules are pure (`LibraryQuery`, `LibraryFiltersPlanning`, `LibraryTabSelection`, `LibrarySelectionPlanning`, `LibraryViewModePlanning`), with JUnit tests.
