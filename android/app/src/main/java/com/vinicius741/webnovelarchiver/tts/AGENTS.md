# Text-to-speech and the player

Applies to `tts/` (including `kokoro/` and `phonon/`), `feature/player/`, and the reader's read-along (`feature/reader/ReaderReadAlong`, `ReadAlongPlanning`). Generated chapter audio is in `narration/AGENTS.md`. These rules add to `android/AGENTS.md`.

- `feature/player/` is the podcast-style TTS player UI: the app-level mini-player bar (`attachTtsMiniPlayer`, docked in the app shell's bottom shelf above the navigation bar while a session is loaded, hidden on Reader, Now Playing and Listen; the Reader docks its own `ReaderPlayerDock` in place of chapter nav while that chapter is read aloud, with a "Back to current sentence" pill when the user scrolls away; the highlight, following and chapter auto-follow live in one per-page `feature/reader/ReaderReadAlong` controller, bound to the WebView's attachment, with rules in `ReadAlongPlanning` and a render-only page script that also pulls the state as a safety net) and the Now Playing screen (`showPlayer`, `AppRoute.Player`). Playback state comes from `TtsEngine.playbackState`; per-story resume positions persist in `tts_positions.json` (see `docs/tts/tts-podcast-player.md`).
- `TtsEngine` plays chapters only from generated packs (`PackTtsOutput`) and loads no speech engine or model. The Listening settings sample (`TtsSamplePreview`, through `TtsOutputs`) renders sentences to `cacheDir/tts_audio/` (`TtsAudioRenderer`, `TtsAudioCache`) with the user-chosen engine (`TtsSettings.enginePackage`): an Android TTS app or a built-in model (`tts/kokoro/BuiltInModels.kt`: Kokoro v1.0 through sherpa-onnx (Kokoro v0.19 is `retired`: not offered, its settings load as v1.0 via `TtsEnginePlanning.withoutRetiredEngine`, its packs still play and servers still run it), Phonon 31M through `tts/phonon/PhononTTS.kt`, JNA over `src/main/jniLibs/*/libptts_ffi.so` rebuilt by `scripts/phonon/build-android-lib.sh`; each downloaded on demand by its `KokoroModelInstaller` and loaded only while in use in its `KokoroRuntime`, both held by `BuiltInEngines` in `AppContainer`, on one thread per fast core (`KokoroThreads`; chapter generation on the phone runs Phonon two sentences at a time on phones with 6+ fast cores and memory to spare, `PhononCopies`); Phonon offers all 37 English catalog voices, listed identically in `BuiltInModels.kt` and `scripts/narration-server/setup.sh` (a test checks), and an older Phonon install downloads only voices added since; a built-in model needs no download when computers generate (live speech then falls back to the phone's engine, `TtsEnginePlanning.standIn`), and the Listening settings sample generates on the computers instead; story-description read-aloud was removed in November 2026 and an old saved description session is never resumed (`TtsSessionPlanning.isResumeEligible`); see `docs/tts/built-in-models.md`; Settings' Kokoro **Test speed** (`KokoroBenchmark`, UI in `feature/settings/SettingsKokoroBenchmark.kt`, debug builds only) times generation on the device and exports a shareable report; see `docs/tts/kokoro-built-in-voices.md`) and plays them as one stream (`TtsPcmPlayer`), falling back to live speech (`LiveTtsOutput`) if rendering fails; see `docs/tts/tts-audiobook-playback.md`. `TtsEngine` tracks its output as one `TtsOutputPhase` (Silent / Running), separate from the persisted pause, and reports playing only when the output is running and not paused. A pause is the listener's decision: only an explicit play or recovery from a brief interruption may start audio, so moves, restores and restarts must keep it. Saved places resolve by their text anchor (`TtsPositionPlanning.resolve`), so bump `TtsTextPreparation.CHUNKING_VERSION` when sentence numbering changes. Do not read repository settings on the main thread before `awaitRepositoryReady`: a restarted service can run ahead of startup, and the first read can deadlock against it.
