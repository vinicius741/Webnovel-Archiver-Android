# Updates and manual sync

Applies to `feature/updates/` and the shared manual sync path. These rules add to `android/AGENTS.md`.

- `operations/ManualStorySync.kt` owns the common manual lookup/fetch/download-plan sequence. URL import and existing-story actions retain their own UI callbacks. The Updates destination (`AppRoute.Updates`) replaced the removed threshold-based bulk Updates / Follow Updates screens: `domain/story/UpdatesPlanning` groups every novel from `ReleaseCadencePlanning` forecasts (May be out, To download, Expected soon, Running late, Recently synced, a 7-day calendar, and the nav badge count).
- `UpdatesScreenModel` (kept in `ScreenModelStore` under `AppRoute.Updates`) owns the screen state: the forecast overview, the filter, the live sync lines and the batch. It plans off the main thread, reusing the plan the nav badge keeps in `UpdatesSyncs.overviewCache` (the first render takes the badge's plan for the same library even when it is older than a minute, then replans), and replans 400 ms after a library or queue change so a download burst plans once. It follows its sources only while the renderer collects. The filter is screen state and resets to All when Updates leaves the history.
- `UpdatesScreen.kt` is the renderer: when the same rows still show it rebinds them and redraws the lead card; a sync line change rebinds only that novel's rows; otherwise it rebuilds the body. Rows (`UpdatesViews.kt`) and the forecast card (`UpdatesForecastCard.kt`) read the state and call model actions; they never call the repository or a sync.
- Syncs from Updates outlive the screen, so they live in the activity-level `UpdatesSyncs` (`ScreenHost.updatesSyncs`), not the model: a row's sync and "Sync all that may be out" run in the activity scope, so a run continues while the user is elsewhere and ends with the activity. Each novel syncs through `StoryWork.syncFromUpdates`, which lists it in `StoryOperations.updatesSyncs` with its progress. A row sync also holds the content slot when free, so the story page shows it; a "Sync all" item never takes the slot and skips the Patreon refresh. Story-page sync, cleanup and EPUB check `StoryOperations.isSyncingFromUpdates` before starting.
- "Sync all" checks novels one at a time, skipping missing, archived, busy (content slot) or already-syncing ones. Large-update reviews and the first blocked source wait for the end of the run; they show at once if Updates is on screen, otherwise the forecast card offers them with Review. Its progress, last summary and held dialogs are `UpdatesSyncs.state`.
