# Domain models and rules

Applies to `domain/` (pure Kotlin: no Android imports, no other app packages; enforced by `ArchitectureRulesTest`). These rules add to `android/AGENTS.md`.

- `domain/model/` contains persisted/application models; `domain/archive/` (ZIP/percent-encoding helpers), `domain/story/`, and `domain/metrics/` contain pure domain rules (including publication-status/source-availability lifecycles, removed-from-source chapter placement (`RemovedChapterPlanning`), the legacy archive-snapshot fold (`LegacyArchiveFoldPlanning`), and per-novel metric-trend snapshot planning/retention). `domain/metrics/MetricSnapshotPlanning.kt` is the single owner of same-day coalescing + downsampling + series extraction + trend direction for the Trends feature; `domain/metrics/TrendAxisPlanning.kt` owns the data-fitted chart Y-range math; `domain/metrics/TrendFilterPlanning.kt` owns the Trends range/metric-family filters (offered ranges, range windows with a carry-in point, LTTB chart downsampling). `domain/download/DownloadJobTransitions.kt` is the single owner of a download job's lifecycle fields (status, retry deadline, retry count, error fields): every move names its legal source statuses, a worker result applies only while the row is still `downloading`, and `DownloadJobTransitionOwnershipTest` fails if other production code assigns those fields. `domain/download/FinishedJobCompaction.kt` owns the stored shape of completed jobs (one compact record per story in `download_queue.json`; see `data/AGENTS.md`). `download/DownloadProcessLoop` and `DownloadSourceReliability` read and write the queue through `DownloadQueueStore` (production wraps `AppStorage`), so `DownloadProcessLoopTest` drives the real scheduling loop on virtual time against an in-memory queue.
