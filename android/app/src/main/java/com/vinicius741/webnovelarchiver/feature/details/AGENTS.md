# Story page

Applies to `feature/details/` (story page tabs, chapter list, Trends). These rules add to `android/AGENTS.md`.

- **Model and renderer.** The story page is the first screen on the screen-model pattern:
  - `StoryPageScreenModel` (one per story, from `storyPageModel(storyId)`, keyed by the Overview route so every tab of the story shares it) publishes `StoryPageUiState`: the model's own copy of the story, its queue jobs, download summary, chapter statuses, pacing and waiting chapters, the story's `StoryOperations.content`/`.ai`, and `coverToReview` (an AI cover waiting in `aiCoverUnseen` or `AiAttention`). It observes its sources only while a renderer collects `state`; a render starts from `refresh()`. Repository reads and writes go through `StoryPageData` (fake it in tests).
  - `storyScreen` builds every tab from that state and starts a `StoryPageRenderer`, which collects the state while the render's root is attached. An operation ending re-renders the tab; an operation starting, or `coverToReview` changing, re-renders the Overview, rebuilds only the inner screen's hero pane beside another tab, or updates the operation strip of a tab without the hero. Progress patches the progress slots, pacing ticks patch only the banner, and download events patch the hero (coverage, CTA, banner) and the chapter rows, held while the chapter list is dragged or flung.
  - Nothing outside the page patches its views. To show new state, publish it (`StoryOperations`, the repository) or add it to `StoryPageUiState`. Click handlers that act on the story read it fresh (the app-bar ⋮ menu reads the model), because download events patch the page without re-rendering it.
  - Sync, cleanup and EPUB run in `operations/StoryWork`; the actions in `feature/story/` keep only busy checks, confirms, toasts and navigation.

- `feature/details/TrendsScreen.kt` (`showTrends`) is the per-novel metric Trends screen, shown as the story page's Trends tab and also reached from the Overview's score pill and Patreon card. `TrendSeriesModel.kt` extracts all series once per open off the main thread; range and metric-family chips rebuild only the card list, and charts attach one per animation frame with no draw-in animation (MPAndroidChart rasterizes in software, so animating every card dropped frames). Charts are built in `feature/details/TrendChart.kt` via MPAndroidChart's `MPChartLib` Android Views module (JitPack, see `settings.gradle`) with Y axes fitted to the data (not pinned to the full metric domain) and a fixed chart height set by the screen. MPAndroidChart 4 uses Kotlin properties and `IAxisValueFormatter`; use its Views module for this app. The details header also patches a small trend arrow beside the score once the history loads (`DetailsHeader.observeScoreTrend`).
