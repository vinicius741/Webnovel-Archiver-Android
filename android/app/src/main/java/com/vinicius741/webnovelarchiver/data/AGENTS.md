# Persistence, backup and diagnostics

Applies to `data/` (`storage/`, `backup/`, `diagnostics/`, `repository/`). These rules add to `android/AGENTS.md`.

- `data/storage/` owns file-based JSON persistence (`AppStorage`), atomic writes, library-index recovery, and backup orchestration helpers. Full-restore crash recovery is the decision table in `RestoreStartupRecovery` (journal phase × live root × snapshot); any change to the swap, rollback or recovery must keep `RestoreCrashRecoveryTest`, which kills each at every filesystem step, passing. Full restore writes the backup's data once: the ZIP extraction is renamed into the staged root and beside the live root (`RestoreTreeMove`, verified-copy fallback when a rename is refused), so the extraction budget is all free space above the reserve, bounded against ZIP bombs by entry count, per-entry size and `MAX_EXPANSION_RATIO`; do not add a copy of the tree to the pipeline. `data/backup/` owns backup/restore planning and validation. `data/diagnostics/` owns local diagnostic export and the persistent activity log (`ActivityLog`, `docs/architecture/activity-log.md`): record an `ActivityLog.record` event with story ids, titles, and counts at each new library-, sync-, download-, or backup-changing decision point, never chapter text, cookies, or keys.
- Downloaded chapters a source stops listing stay in the story flagged by `Chapter.removedFromSourceAt`, at their old reading position (`docs/sources/removed-from-source-chapters.md`). Never create a separate story copy for them; full sync flags, keeps, and un-flags them, and JSON backup merges must not drop them. Legacy `isArchived` snapshot stories are folded into their live story at startup and after restore/import (`data/storage/LegacyArchiveFold.kt`); an unfolded leftover stays read-only for sync and download. Every sync commit runs `RemovedChapterPlanning.restoreLostDownloads`, so downloaded text is never dropped implicitly. Do not add a bulk delete for removed-from-source chapters: a former "Discard" button on the Details notice was mistaken for dismissing it and destroyed the only copy. Backups are full ZIPs only (Create / Restore in Data & backup); JSON export/import and Recover chapters from backup were removed in November 2026 (the JSON importer stays for instrumentation seeding). Clear local storage keeps the `backups` folder.
