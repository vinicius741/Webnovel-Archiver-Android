Code Simplification Audit

The project does not need an architectural rewrite. Its strongest simplification path is subtraction: remove obsolete seams, consolidate repeated projections and mutations, and replace view-tree/index conventions with typed state. This report records 40 concrete opportunities with examples and the behavior each change must preserve.

Executive verdict

Prefer a sequence of narrow consolidations over a new layer or framework. The existing package boundaries are generally sensible. Complexity is concentrated in parallel representations of the same state, compatibility facades that survived their migrations, and UI code that encodes structure by child position or reconstructed signatures.

Part I — Delete obsolete surfaces

1. Remove production APIs with no production consumer

P0

LibraryPresenter.kt; EpubEngine.lastCleanupResult; DownloadEngine.onChanged; unused TTS aliases and counters

LibraryPresenter is unreferenced. Several public properties and wrappers are only referenced by their declaring file or tests. Their visibility implies extension points that do not exist and makes ownership harder to see.

Current
fun close() = shutdown()
fun currentChunkCount() = chunks.size
var onChanged: (() -> Unit)? = null
Simpler
// Call shutdown() at the service boundary.
// Delete counters/callbacks after a usage search.
// Delete LibraryPresenter as one atomic change.

Check: search production, tests, reflection, XML handlers, and serialization names before deletion. Keep test seams that model real boundaries.

2. Retire the TextCleanup compatibility facade

P0

cleanup/TextCleanup.kt, HtmlCleanup.kt, CleanupEngine.kt

The facade forwards to three newer owners, while HtmlCleanup.applyDownloadCleanup retains a second stateless implementation beside the cached production engine. Move callers to the real owners, delete the facade, and make compiled rules one object rather than parallel lists.

Current
TextCleanup.applyRules(text, rules)

private val rules: List<CleanupRule>
private val regexes: List<Regex>
Simpler
cleanupEngine.clean(text)

data class CompiledRule(
  val rule: CleanupRule,
  val regex: Regex,
)

Preserve: rule ordering, invalid-regex handling, download versus TTS semantics, and cache behavior. Golden output tests should precede deletion.

3. Remove the dead TTS chunkSize setting

P0

TtsTextPreparation.kt, Models.kt, PreferenceNormalization.kt

The setting is normalized and persisted but does not control chunking; preparation uses sentence boundaries with an 800-character maximum.

// Current
prepare(text, chunkSize = preferences.chunkSize) // ignored

// Simpler
prepare(text) // policy is explicit inside preparation

Old JSON can safely contain an extra property, but add a compatibility test before removing the model field.

Part II — Merge duplicated behavior and state

7. Give story sync one commit operation

P0

feature/story/StoryActions.kt, sync/SyncEngine.kt, data/AppRepository.kt

Manual and bulk sync repeat lookup, fetch, publish, pending-download calculation, auto-queue logic, cancellation, and source blocking. SyncEngine also writes storage while repository state is published elsewhere. Keep presentation callbacks separate, but merge the domain operation and make the repository the mutation owner.

Current
val updated = provider.fetch(existing)
storage.upsertStory(updated)
repository.publishLibraryChanged()
calculatePending(updated)
maybeAutoQueue(updated)
Simpler
val result = storySync.sync(storyId)

repository.commitSyncedStory(
  story = result.story,
  metrics = result.metrics,
)

Preserve: per-story sync lock, cancellation, source reliability fences, metrics snapshots, and the difference between UI messages and durable state.

8. Use one download-count projection

P0

DownloadManagerPlanning.kt, DownloadDetailsPlanning.kt, DownloadScheduler.kt, DownloadEngine.kt

Queued, active, completed, failed, and total counts are derived in at least four shapes. Centralize the fold and adapt it for each screen.

Current
QueueStatusCounts(...)
StoryDownloadSummary(...)
DownloadProgress(...)
// plus manual counters in DownloadEngine
Simpler
data class DownloadCounts(
  val queued: Int,
  val active: Int,
  val completed: Int,
  val failed: Int,
)

fun Iterable<DownloadJob>.counts(): DownloadCounts

Screen models may still expose different labels; they should adapt from the same arithmetic.

9. Combine queue mutation and restart paths

P0

download/DownloadEngine.kt, DownloadQueuePlanning.kt

resume and retry mutate, publish, and start work through nearly identical paths. Queue action and target should be one command.

sealed interface QueueCommand {
  data class Resume(val id: JobId) : QueueCommand
  data class Retry(val id: JobId) : QueueCommand
}

private fun mutateAndStart(command: QueueCommand)

Retain atomic enqueue behavior and do not merge away the second source-acceptance fence.

10. Require repository-backed TTS in production

P0

tts/TtsEngine.kt, TtsPlaybackPreparation.kt, TtsSessionStore.kt

The app container always constructs TTS through the repository, yet storage-backed production alternatives remain. Keep interfaces for tests; remove unused production implementations.

// Current
TtsEngine(storageSource, storagePersistence)
TtsEngine(repositorySource, repositoryPersistence)

// Simpler production graph
TtsEngine(repository)

11. Model the TTS cursor as “current,” not “next”

P1

tts/TtsEngine.kt, TtsSessionPlanning.kt

The engine post-increments its chunk index and then compensates in pause, previous/next, watchdog, restore, and error paths. A single currentChunkIndex removes offset helpers and makes persistence literal.

Current
val chunk = chunks[nextIndex++]
persist(index = nextIndex - 1)
fun previous() = seek(nextIndex - 2)
Simpler
val chunk = chunks[currentChunkIndex]
persist(index = currentChunkIndex)
fun previous() = seek(currentChunkIndex - 1)

This is high-touch: lock down restore, skip, pause, watchdog, and utterance-error tests first.

12. Expose TTS state through one observable stream

P1

TtsEngine.kt, TtsForegroundService.kt, reader TTS UI

Multiple callbacks create ordering questions. Publish a state snapshot and derive UI/service behavior from it.

data class TtsPlaybackState(
  val status: Status,
  val chapterId: String?,
  val chunkIndex: Int,
)
val state: StateFlow<TtsPlaybackState>

Do not turn durable commands into UI scope work; service ownership remains.

14. Normalize preferences once, then persist one object

P1

PreferenceNormalization.kt, SettingsValidation.kt, AppStorage.kt, RestoreStagingWriter.kt, AppRepository.kt

Normalization currently crosses feature and data packages and may be repeated during read, restore, and write. Move the rules to a neutral settings/domain package, normalize at ingress, and use one repository config-write helper.

Current
repository.setFontSize(normalizeFontSize(value))
repository.setLineHeight(normalizeLineHeight(value))
repository.setTheme(normalizeTheme(value))
Simpler
repository.updatePreferences { current ->
  current.copy(reader = requestedReader).normalized()
}

Preserve: restore validation, backward-compatible defaults, and equality-based suppression of redundant writes.

15. Make EPUB selection and progress typed

P1

epub/EpubSelection.kt, EpubEngine.kt, StoryContentActions.kt

Bound selection and progress cross boundaries as strings and are parsed back with regex. Return values the caller can use directly.

data class EpubProgress(val completed: Int, val total: Int)
data class ChapterRange(val first: Int, val last: Int)

engine.export(range) { progress: EpubProgress -> ... }

Also remove normalizeCoverMediaType branches that only handle a content type never supplied by the caller.

16. Route atomic text and bytes through one stream writer

P1

data/AtomicFileWrites.kt

Text and byte overloads repeat temporary-file, flush, sync, rename, and fallback mechanics.

fun writeAtomically(file: File, write: (OutputStream) -> Unit)

fun writeText(file: File, text: String) =
  writeAtomically(file) { it.writer().use { w -> w.write(text) } }

Preserve fsync and fallback ordering exactly; this is structural deduplication, not a durability rewrite.

17. Parse a typed backup manifest after raw validation

P1

BackupExporter.kt, FullBackupManifestValidation.kt, FullBackupRestorer.kt, RestoreStagingWriter.kt

Manifest keys and conversions are repeated. Validate untrusted JSON first, then hand later stages a typed, already-checked model.

val raw = readManifest(zip)
validateRawManifest(raw) // limits and hostile input checks
val manifest = FullBackupManifest.fromValidated(raw)
restore(manifest)

Do not collapse archive limits, path traversal checks, staging, commit, or rollback into one “convenient” restore function.

Complexity that is earning its keep

Simplification should reduce accidental complexity without flattening the safety boundaries below.

Download ownership

Keep one durable owner, atomic enqueue, foreground-service rules, pacing, circuit state, and the second acceptance fence that catches a source becoming blocked mid-request.

Backup restore

Keep archive limits, raw manifest validation, path traversal defenses, staging, commit, rollback, and the distinct privacy scrubs. They are separate failure barriers.

Reader and WebView safety

Keep navigation policy, content isolation, teardown, Cloudflare access flow, external custom-tab flow, and root-instance guards separate even when helpers are shared.

TTS lifecycle

Keep audio focus, wake/foreground ownership, watchdog, persisted session recovery, utterance correlation, and shutdown cleanup. Simplify the state model around those guarantees.

Sync and EPUB

Keep per-story synchronization, stable chapter identity, metric capture, streamed EPUB output, cancellation, and partial-file cleanup.

Responsive UI

Keep fold/window planning, drag selection, ConcatAdapter headers, coverage-bar drawing/accessibility, and deliberately different button dimensions.

Recommended implementation order

  1. Lock behavior down: add golden cleanup tests, TTS cursor/restore tests, download-count projection tests, backup compatibility tests, and an exact detekt baseline.
  2. Delete first: remove verified dead APIs, chunkSize, obsolete aliases, historical comments, and the cleanup facade.
  3. Unify domain ownership: repository sync commit, common download counts, queue mutate-and-start, repository-only TTS production wiring, and normalized preference writes.
  4. Replace implicit UI contracts: Details bindings, persistent RecyclerView holders, typed queue UI models, typed progress wrappers, and KTX text listeners.
  5. Simplify TTS state: move to a current-index cursor, then a single state stream. Keep this separate from the deletion tranche because it has broader runtime risk.
  6. Reorganize files last: split screens and model files only after responsibilities and duplicate logic have converged.

Definition of “simpler” for this project

A successful change should remove a state representation, duplicate branch, public surface, or ownership ambiguity—not merely move lines to another file. Track production line count, function count, detekt findings, and test coverage, but review the number of competing state models and mutation paths as the primary signal.

Audit method and limitations

This was a repository-wide static pass over the native Kotlin production and test sources, existing architecture/QA documents, dependency direction, call sites, and complexity output. A fresh :app:detekt --rerun-tasks run completed successfully and reported 45 accepted findings (primarily large function/type counts, enum naming, long parameter lists, and cyclomatic complexity). The pass intentionally made no production changes and did not claim runtime defects.

Line numbers are intentionally omitted because several files are actively changing; filenames, symbols, and code shapes are the durable locators. Every deletion still requires a fresh usage search at implementation time. The opportunities are prioritized by leverage and confidence, not by raw file size.
